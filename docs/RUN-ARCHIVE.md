# Local game archive

Darkspire records game state only. It does not send logs to a server. Use **Export run archive** to save the JSON archive, then provide that file for analysis. The assistant cannot automatically inspect another browser's storage or a remotely hosted player's archive.

The expedition ledger requires player identity before a new run or resume. Humans choose a name. AI testers explicitly provide provider, exact model ID, model version and thinking effort; unavailable values must be entered as `unknown`. Scripted testers provide policy and version, with effort recorded as `not applicable`. Every event carries its immutable actor; changing players does not rewrite earlier attribution. Identity remains in this tab's session storage and can be changed with **Change player**. No browser/device identity is inferred.

The recorder stores version/seed availability, expedition and session IDs, initial party/deck/equipment, combat hands and hidden piles, enemy intents, actions, damage/status/death events, route changes, rewards offered, gear operations, settlement and state changes after game interactions. Functions are omitted; the matching released source version is required to interpret card rules. Diagnostic archives deliberately contain hidden state; gameplay policies must never receive the archive as their observation.

Native IndexedDB holds committed events, losslessly gzip-compressed when the browser supports CompressionStream. A synchronous localStorage journal protects pending writes when a tab closes; the next session replays that journal. Each event has a unique session/event ID. Export waits for pending writes, decompresses durable records, combines uncommitted memory, and includes corrupt journal entries without deleting them. There is no automatic run deletion or retention cap.

Storage is finite and browser-owned. A write failure is shown beside the export button, and events that failed local storage remain in memory for export. Export before closing if warned. Clearing browser data removes the local archive; this is not an off-device backup. Export currently assembles the archive in memory, so very large histories still need a streaming export follow-up. Full snapshots prioritize diagnostic fidelity over space; compact lossless deltas remain a follow-up.

Run `node sims/analyze-archive.js exported-archive.json report.json` to summarize actual damage, absorbed block, card frequency, deck/equipment changes and outcomes per expedition. Damage per energy is observational: damage from statuses and relics is included, so this does not establish causal card efficiency or prove that a build is balanced. Avoidable-death counterfactuals require replay support and are not claimed.

Verification: `node tests/telemetry.js` checks the actual shipped script order, snapshots, damage, reload continuity, archive retention across campaign reset and quota failure. `node tests/archive-analysis.js` checks numerical attribution. Serve the project locally and open `tests/telemetry-fixture.html` for native IndexedDB, real campfire embark/save/load and export-control checks; its campaign storage and database are isolated from normal play.
